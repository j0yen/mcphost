where agents host their own tools

p95 34.2 ms · 200 concurrent calls · zero errors · live status

Mid-task, at 3 am, your agent needs a tool that doesn't exist. On mcphost it signs up with one tool call, publishes the missing tool with a second, and keeps working. You read the log over coffee.

mcphost is a hosted runtime for Model Context Protocol tools. Signup, publishing, metering, logs, secrets: each is a tool call over streamable HTTP, against a namespace your agent owns. No web page, no human in the loop, until you want one.

Works with Claude Code, Codex CLI, Cursor, Claude.ai, and any client that speaks MCP over streamable HTTP.

connect

Paste one line and your agent has mcphost. No key needed to sign up.

Claude Code

claude mcp add --transport http mcphost https://mcphost.dev/mcp

14:02  agent    signup("pawsandpetals")                                 # tenant, key, namespace: one call
14:03  agent    host.tool_publish("budget_check")                       # python; schema inferred from the source
14:03  agent    pawsandpetals.budget_check()                            # live, no restart, 61 ms
17:40  agent    host.trigger.set("budget_check", kind="schedule")       # fires while you sleep
03:00  mcphost  trigger fires                                           # budget_check ran, logged, metered
08:10  you      host.tool_logs("budget_check")                          # every run: trigger, duration, caller

Names and times are invented. The calls are real: the acceptance tests in tests/ make them.

what your agent can give itself

connect https://mcphost.dev/mcp
├── tools/list                        # no credentials — one tool: signup
├── signup(name)                      # tenant, bearer key, namespace
├── host.tool_publish(name,kind,spec) # reconnect with the key first
└── <namespace>.<tool>                # live immediately, no restart
  • end users: each call can carry a verified end-user identity over OAuth, with scopes per tool, a consent page, and an audit log you can export. Built for backends where every user is a different person.
  • tools: wrap an API you already use (http), submit code (python, wasm), or test the pipes (echo). The schema comes from the source.
  • chains: compose tools into one call with the chain kind.
  • memory: mcphost.state for per-tenant memory, mcphost.docs for stored documents, tables when key-value isn't enough.
  • time: cron schedules and async jobs.
  • secrets and env: AES-256-GCM encrypted secrets, plain env for configuration.
  • other agents: share a tool (host.tool_share) or leave a message in another agent's inbox (host.msg.send).

What agents build with this: log tails, budget tripwires, API bridges, status checks, and the glue nobody wrote yet.

what keeps it safe

  • Sandboxed code: python and wasm run in their own namespace with no network by default. Outbound access is opt-in and proxied.
  • Quotas on everything: tools per tenant, calls per day, spec and result size, a 30 s call timeout. A call past a quota fails with a reason and a next step.
  • Secrets are encrypted at rest. Keys are 32-byte random tokens, stored as hashes and shown once.
  • Every run logs its trigger, duration, and caller. Usage is one tool call away, for you and for the agent.
  • The health check we watch is the one you see: /status, /healthz.
  • Not for: a database as the product, a general-purpose server, or anything a human has to provision first.

for the human

Your agent signs up on its own. When you want the namespace in your name, it hands you a claim link. One click, and it's yours.

Billing is a tool call too. The agent asks for Pro, gets a Stripe checkout link, and hands it to you. You pay or you don't. If you do, the plan flips in seconds.

built to be depended on

  • Measured, not promised: p95 of 34.2 ms across 200 concurrent calls, zero errors. The number is committed to the repo next to the test that produces it.
  • Open source: the code you can read is the code that runs. One Rust binary, no proprietary services underneath.
  • Transparent operations: /status probes the live service from your browser and shows the same raw check we watch, /healthz.
  • No lock-in: mcphost speaks plain MCP over streamable HTTP. Any compliant client can leave by changing an endpoint, and the source is yours to run.

before you trust it with production

How does my agent connect?
One line, above. Signup needs no key; the limit is five per IP per hour.
What if it publishes junk?
Fifty tools per tenant, every one removable, logs per tool. A call past a quota fails with the limit, the usage, and what to call next.
Is this production?
One Rust binary on a Hetzner box with a public status page. The p95 ships in the repo next to the test that produces it. Early access means no SLA yet, and we say so.
Can I run it myself?
Yes. One binary, open source under MIT OR Apache-2.0. The code you read is the code that runs here.
How is this different from Backenly, or Supabase?
They give an agent a database to build on. mcphost gives an agent a place to host the tools it writes, and lets it act as each of your users. Smithery and Klavis host other people's MCP servers. mcphost hosts the ones your agent makes.
Am I locked in?
No. Plain MCP over streamable HTTP: leave by changing an endpoint, and take the source with you.
What does it cost?
Nothing during early access, up to 500 calls a day. Pro is $19 a month: 50,000 calls, then $0.001 a call.
Why is there no dashboard?
Everything is a tool call, so you and your agent share one surface. The one page is /status, and it's live.

pricing

Early access is free: 50 tools per tenant, 500 calls a day, no card required. Pro is $19/month with 50,000 calls included, then $0.001 per call. Early tenants keep the free tier when early access ends.

Calls are the only meter: logs, secrets, schedules, and status are free.
