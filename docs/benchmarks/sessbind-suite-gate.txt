Session binding landed on mcphost's own session identity, not rmcp's.
rmcp 3.3.0's only built-in Mcp-Session-Id mechanism (legacy_session_mode(true))
makes the transport require the header back on every follow-up request, which
the Claude Agent SDK's own recorded wire sequence never sends -- so
src/http.rs's build_router still runs with_legacy_session_mode(false) and
http::issue_session_id mints an HMAC-signed session id one layer above the
transport. That break is pinned by a test that builds the exact production
router with the flag flipped, not asserted in prose:
sessbind_ac01_keyless_call_after_signup_runs_as_the_bound_tenant.rs::
enabling_rmcps_own_session_mode_would_break_claude_sdk_replay. The shipped
SDK compat guarantee (tests/compat_ac11_ac12_claude_sdk_replay.rs) is
unchanged and green in the run above.
