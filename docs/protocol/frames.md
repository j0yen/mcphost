# Response frames per request type

Generated by `scripts/protocol-frames-check.sh` from `FRAME_SEQUENCES` in `src/protocol/frames.rs`; do not hand-edit.

Protocol version: `2026-07-28`. A response is one JSON-RPC document unless a frame precedes the result on the same request, in which case it upgrades to `text/event-stream` carrying every frame in order. `{1}` = exactly one, `{0,1}` = optional, `{0,n}` = any number.

Every `/mcp` response carries `Server-Timing: app;dur=<ms>`: the host's wall time from the request reaching the route (auth and rate-limit time included) to the response head being ready, so a `text/event-stream` response reports time to response head, not to its last frame. Caddy, TLS and network time are not included.
